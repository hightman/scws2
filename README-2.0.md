# SCWS 2.0 开发

目标是面向社区、CMS 检索的纯 C 词典分词工具包，运行时无第三方依赖，继续提供 PHP 扩展。2.0 接受 API 和词典格式不兼容；只支持 UTF-8，删除关键词提取及 IDF。名称暂沿用 SCWS。

词典保留最多两个 ASCII 字符的可选词性，jieba `nrt`、`nrfg` 在加工时归并为 `nr`，缺失时为空，不参与切分评分。姓名、地名、词性倍率规则已明确移除，词性只作标签。当前唯一接入的上游是 jieba 标准词典，THUOCL 尚未融入。

开发顺序：

1. **词典**：固定来源和许可、可追踪修订、加工评分、纯 C XDB2 编译器、独立校验和词表差异报告。已实现首条 jieba 基础词典流水线；仍需新词补充来源和检索质量评估。
2. **核心库与测试**：已实现只读共享词典、严格 UTF-8/英文数字处理、候选 DAG、动态规划、standard/search 模式、叠加词典和可区分来源的补词。库、CLI、API 生命周期及多线程共享测试已落地，仍需真实检索质量及跨平台评估。
3. **PHP 扩展**：薄封装对象接口，结果与 C 核心一致。尚未实现。

第一阶段用法与限制见 [dict/README.md](dict/README.md)，文件契约见 [dict/FORMAT.md](dict/FORMAT.md)。旧引擎、字符集层、Autotools 构建及依赖旧 API 的历史演示已从本分支移除，Git 历史和主分支保留对照实现。PHP 扩展等待核心稳定后重写。

规则统一为 `src/rules.ini`，同一份 UTF-8 数据包含简繁写法，仅保留 `symbol`、`chnum0–5`、`munit`。`make` 按依赖时间自动生成 `build/rules_data.h`，生成代码不进入 Git。已实现保守的数字和数量识别及符号分类，不引入旧通用 INI 解释器。支持边界见 `src/RULES.md`。

`make` 构建核心与 CLI，`make check` 执行离线测试；API 契约参见 `API.md`。核心不再含字符集切换代码。搜索补词的歧义筛选仍待评估，基础词典旧词及新词不足问题不会因替换解码算法自动消失。

正式发布前建立分词与小型检索评估集，测量召回、误召回、词数、内存与速度；未验证的词典更新不自动发布。引擎代码采用现有 `COPYING`，词典包单独附带各数据来源的许可。
