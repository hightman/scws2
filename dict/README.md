# scws2 词典

普通使用者可从 [GitHub Releases](https://github.com/hightman/scws2/releases) 下载预构建词典，无需自行构建。下载、源码构建及显式配置路径的完整流程见[根目录 README](../README.md#词典准备与配置)。

目前交付的是可复现的基础词典构建链路；尚未完成检索质量评估，不能视为正式 2.0 词典。核心库及 PHP 扩展状态见根目录 README；旧版程序不能加载本目录生成的 XDB2。

## 维护入口

本目录集中维护词典流水线及其输入：`build.py` 提供下载、加工、构建、校验和差异报告；`sources.lock.json` 锁定来源，`overrides.tsv` 保存人工修订，`jieba.LICENSE` 保存数据许可，`FORMAT.md` 定义 XDB2 格式。

通用纯 C 词典编译器位于 `tools/scws2-dict.c`。原始下载保存在 `dict/.cache/`，构建产物保存在 `dict/build/`；两者均不进入 Git。

## 独立构建

在本目录执行，不需要先构建核心库。维护词典需要 C11 编译器和 Python 3.9+，不依赖第三方 Python 包。

```sh
cd dict
make
make check
make install PREFIX="$HOME/.local/scws2"
```

`make` 先编译纯 C 的词典编译器，再按 sources.lock.json 的尺寸和 SHA-256 校验 `.cache/`。仅在缓存缺失或不匹配时下载固定版本，验证成功后原子替换，不查询浮动上游。`python3 build.py build` 仍为离线入口；`fetch` 可以单独执行。

输出在 `dict/build/`：`dict.xdb` 是固定名称的运行时词典，`lexicon.tsv` 是加工词表，`manifest.json` 记录来源、加工、编译器及结果哈希，`LICENSE.jieba` 是上游许可。缓存和产物不提交 Git。

## 安装与预构建包

显式 PREFIX 优先；未指定时查询父项目 configure 的前缀，再依次检查 `/usr/local`、`/usr/local/scws2`、`~/.local/scws2`。自动选择必须找到 `include/scws2.h`，否则报错要求 PREFIX，不只检查目录是否存在。显式 PREFIX 可创建新目录。

```sh
make install PREFIX=/usr/local/scws2 DESTDIR=/tmp/scws2-package
```

安装为 `$PREFIX/etc/dict.xdb`，附带 LICENSE.jieba 和 manifest.json；不安装词表或编译器。目标同样新或更新则跳过；以同目录临时文件和原子替换更新词典，不截断正在 mmap 的旧文件。C/PHP 调用方须显式指定路径。`make install` 不下载或构建，缺少产物时报错。

发布包 `scws2-dict-YYYYMMDD.tar.gz` 直接附带词典和安装 Makefile，解压后 `make install PREFIX=...` 即可，不需要 Python、C 编译器或完整源码仓库。日期使用 UTC+8，词典发布与核心版本独立，也可附于同一个核心 Release。未变化的词典通过固定历史资产 URL 复用，不覆盖同名资产。

## 固定来源

首个基础源是 [jieba 标准词典](https://github.com/fxsjy/jieba/blob/master/jieba/dict.txt)，由 `sources.lock.json` 锁定完整 commit、字典与许可文件的 URL、大小和 SHA-256。当前快照所在提交是 2020 年，提供基础词表，不代表现代新词覆盖已经解决。THUOCL、输入法词典尚未接入，也未完成其逐文件来源审计。

首次获取后，应将原始缓存作为发布归档的一部分保存；Git 不跟踪 `dict/.cache/` 和构建产物。第三方来源不与引擎代码混用许可证。

## 加工与权重

1. 严格校验 UTF-8 和输入列；丢弃含空白、控制/格式字符、超过 240 字节的词条，并记录数量。当前不做简繁、大小写、NFKC 等转换，防止擅自合并不同词面。
2. 先将 jieba `nrt`、`nrfg` 显式映射为 `nr`；其余标签保留，未定义的长标签报错，不直接截断。单个来源内的重复词取最大频率，不相加，保留该行映射后的词性；同频优先有词性的行，再按词性 ASCII 序择一，结果不依赖输入顺序。记录映射及词性冲突数量；零频条目不采用。上游没有词性时为空。
3. 应用四列 `term / action / frequency / pos` 的 `overrides.tsv`。每个词只允许一条修订，操作分别为：`upsert`（必须指定正整数频率）、`deny`（移除完整词资格，频率和词性留空）、`search`（只作检索补词，频率留空）。词性留空表示沿用原标签，新词默认未知；`-` 表示明确清空。被 deny 的词仍可能作为其他词的前缀存在，不代表仍可作为词输出。
4. 主词代价为 `round_half_up(-ln((frequency + 1) / (sum_frequency + main_entries)) * 1024)`；只补词的代价为 0，不参与主路径。基础源提供的频率是初始先验，不等于经过本项目验证的真实词概率。
5. C 编译器生成必要的 Unicode 字符边界前缀，并构建平衡哈希搜索树；独立 Python 校验器检查头部、指针、树序、桶归属、全部记录及前缀闭包。

上游频率和人工频率必须处于相同的基础源评分口径；今后接入 DF、输入法权重等新来源时要新增明确的转换规则，不能直接求和。修改任何影响结果的规则时提升加工版本。

词性标签见 [POS.md](POS.md)。词性仅作可选元数据，最多两个 ASCII 字符，格式为 `[A-Za-z][A-Za-z0-9_-]?`；缺失值为空，不能用已有标签 `x` 替代未知。人工修订只能写映射后的短标签，例如 `nr`。当前映射集合标记为 `jieba-compact-v1`，映射表写入构建清单，原始标签保存在上游快照中；不代表已经统一全部旧版词性规则语义。前缀节点不继承长词词性，兼为完整词时保留自身标签。词性不参与评分；旧词性倍率规则已决定移除，不参与切分评分。

## 运行时自定义词表

小型增补词表可直接用 `SCWS2_DICT_TEXT` 加载，无需先运行加工脚本。支持一行一词，或空格/Tab 分隔的 `词条 词频 词性`，也接受词性与词频交换顺序；默认词性 `un`，缺省/零词频为 `1`，同词最后一行生效。详细格式及词频范围、参考档位见 [C API](../API.md#文本词典)，标签说明见 [POS.md](POS.md)。

运行时以固定参考代价 `max(0, round(18432 - 1024 * ln(max(frequency, 1))))` 转换权重，不使用文本文件总频率作分母；增减无关词不会改变已有词代价。所有词具有 MAIN 和 SEARCH 资格，不支持 `deny` 或只补词修订。文本编译为临时 XDB2 后跨进程复用；TEXT 默认请求 mmap，组合 `SCWS2_DICT_TEXT | SCWS2_DICT_MEMORY` 可强制内存加载；不可用时退回内存。首次编译需要额外构建内存，后续加载检查源词表元数据，不直接 mmap 文本。缓存路径、加锁及失效规则见 [C API](../API.md#临时缓存与加载模式)。

这一入口方便应用补词，不替代带来源锁定、修订、许可和清单的基础词典发布链路；离线流水线仍保留其归一化评分及重复词处理规则。大型基础词典建议预编译后用 MMAP，避免每次解析和每进程私有副本。

## 当前基础快照

已用锁定数据生成 349,045 个完整词条、498,113 个含前缀节点。当前上游长标签只有 `nrt`（5,941 行）和 `nrfg`（484 行），均归并为 `nr`；没有新增词条，文件大小和校验和以构建清单为准。18 项离线测试覆盖映射、两字符边界、未知值、修订、非法标签、仅词性差异不改变代价及旧格式拒绝；尚未做跨平台或真实检索质量验收。

抽样发现基础词表缺少“大模型”“短视频”“直播带货”“数字人民币”等完整词条。这不直接等于无法通过子词召回，但说明新词补充仍是进入正式发布前的必要工作。当前修订表为空，不用临时手填几个流行词冒充长期维护的数据来源。

## 更新与发布

更新时修改完整 commit 和两个源文件的校验信息，先归档旧缓存与输出目录用于比较；下次 `make` 会按新锁文件重新下载不匹配的源文件，也可指定独立缓存目录手动 fetch/build。先检查新增、删除、频率及切分差异，通过检索评估后再发布；不自动追踪浮动分支、不自动发布。

可用 `python3 dict/build.py diff build/dict-old build/dict-new` 比较两个加工目录，输出新增、删除、代价、用途与词性变化统计及有限样例；`--limit` 控制样例数。支持比较旧的无词性加工目录与当前四列词表。评分分母随主词集合变化，一次修订可能影响很多词的代价，须结合实际切分差异判断。

当前没有自动更新锁文件，尚未发行正式词典版本；后续将结合核心库补充分词与检索差异评估。复现要求相同输入、加工规则与数值行为；极少数处于舍入边界的浮点结果可能受平台影响，发布流水线应固定工具环境并核对输出哈希。后续需要跨平台逐字节验证。

构建先在临时目录完成编译和校验，成功后更新输出文件，清单最后写入。它不是多文件原子发布；服务部署应使用独立版本目录并切换目录引用，不在正在加载的目录直接重建。
