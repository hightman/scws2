# SCWS 2 词典

目前交付的是可复现的基础词典构建链路；尚未完成检索质量评估，不能视为正式 2.0 词典。核心分词库与 PHP 扩展随后开发，旧版程序不能加载本目录生成的 XDB2。

## 构建

在仓库根目录执行。需要 C11 编译器和 Python 3.9+，均不依赖第三方包。

```sh
mkdir -p build
cc -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror tools/scws2-dict.c -o build/scws2-dict
python3 tools/dict.py fetch
python3 tools/dict.py build
python3 tools/dict.py check build/dict/dictionary.xdb
python3 -m unittest discover -s tests -p 'test_dictionary.py' -v
```

只有 `fetch` 联网；`build` 不自动下载，缓存不存在或校验失败时退出。发布包使用预先生成的 XDB，无需 Python 或网络。独立 C 编译器接受 `lexicon.tsv output.xdb`，不依赖 Python。

输出目录 `build/dict/` 包含：

- `lexicon.tsv`：UTF-8 字节序排序的四列 `term / cost / flags / pos`，最后一列可为空。
- `dictionary.xdb`：保留可选词性、不含 IDF 的 XDB2 schema 3 文件；旧 schema 1/2 产物需重建。
- `manifest.json`：来源 commit、源文件 SHA-256、加工版本与代码指纹、编译器指纹、修订及结果校验和、统计。
- `LICENSE.jieba`：随词典分发的上游 MIT 许可。引擎许可参见根目录 `COPYING`。

## 固定来源

首个基础源是 [jieba 标准词典](https://github.com/fxsjy/jieba/blob/master/jieba/dict.txt)，由 `sources.lock.json` 锁定完整 commit、字典与许可文件的 URL、大小和 SHA-256。当前快照所在提交是 2020 年，提供基础词表，不代表现代新词覆盖已经解决。THUOCL、输入法词典尚未接入，也未完成其逐文件来源审计。

首次获取后，应将原始缓存作为发布归档的一部分保存；Git 不跟踪 `.cache/dict/` 和构建产物。第三方来源不与引擎代码混用许可证。

## 加工与权重

1. 严格校验 UTF-8 和输入列；丢弃含空白、控制/格式字符、超过 240 字节的词条，并记录数量。当前不做简繁、大小写、NFKC 等转换，防止擅自合并不同词面。
2. 先将 jieba `nrt`、`nrfg` 显式映射为 `nr`；其余标签保留，未定义的长标签报错，不直接截断。单个来源内的重复词取最大频率，不相加，保留该行映射后的词性；同频优先有词性的行，再按词性 ASCII 序择一，结果不依赖输入顺序。记录映射及词性冲突数量；零频条目不采用。上游没有词性时为空。
3. 应用四列 `term / action / frequency / pos` 的 `overrides.tsv`。每个词只允许一条修订，操作分别为：`upsert`（必须指定正整数频率）、`deny`（移除完整词资格，频率和词性留空）、`search`（只作检索补词，频率留空）。词性留空表示沿用原标签，新词默认未知；`-` 表示明确清空。被 deny 的词仍可能作为其他词的前缀存在，不代表仍可作为词输出。
4. 主词代价为 `round_half_up(-ln((frequency + 1) / (sum_frequency + main_entries)) * 1024)`；只补词的代价为 0，不参与主路径。基础源提供的频率是初始先验，不等于经过本项目验证的真实词概率。
5. C 编译器生成必要的 Unicode 字符边界前缀，并构建平衡哈希搜索树；独立 Python 校验器检查头部、指针、树序、桶归属、全部记录及前缀闭包。

上游频率和人工频率必须处于相同的基础源评分口径；今后接入 DF、输入法权重等新来源时要新增明确的转换规则，不能直接求和。修改任何影响结果的规则时提升加工版本。

词性仅作可选元数据，最多两个 ASCII 字符，格式为 `[A-Za-z][A-Za-z0-9_-]?`；缺失值为空，不能用已有标签 `x` 替代未知。人工修订只能写映射后的短标签，例如 `nr`。当前映射集合标记为 `jieba-compact-v1`，映射表写入构建清单，原始标签保存在上游快照中；不代表已经统一全部旧版词性规则语义。前缀节点不继承长词词性，兼为完整词时保留自身标签。词性不参与评分；旧 `rules.ini` 词性规则尚未迁移，后续如何使用另行设计。

## 当前基础快照

已用锁定数据生成 349,045 个完整词条、498,113 个含前缀节点。当前上游长标签只有 `nrt`（5,941 行）和 `nrfg`（484 行），均归并为 `nr`；没有新增词条，文件大小和校验和以构建清单为准。18 项离线测试覆盖映射、两字符边界、未知值、修订、非法标签、仅词性差异不改变代价及旧格式拒绝；尚未做跨平台或真实检索质量验收。

抽样发现基础词表缺少“大模型”“短视频”“直播带货”“数字人民币”等完整词条。这不直接等于无法通过子词召回，但说明新词补充仍是进入正式发布前的必要工作。当前修订表为空，不用临时手填几个流行词冒充长期维护的数据来源。

## 更新与发布

更新时修改完整 commit 和两个源文件的校验信息，用新缓存目录下载验证；不要覆盖锁定文件后复用不匹配的旧缓存。保留旧快照与输出目录用于比较。先检查新增、删除、频率及切分差异，通过检索评估后再发布；不自动追踪浮动分支、不自动发布。

可用 `python3 tools/dict.py diff build/dict-old build/dict-new` 比较两个加工目录，输出新增、删除、代价、用途与词性变化统计及有限样例；`--limit` 控制样例数。支持比较旧的无词性加工目录与当前四列词表。评分分母随主词集合变化，一次修订可能影响很多词的代价，须结合实际切分差异判断。

当前没有自动更新锁文件，尚未发行正式词典版本；分词差异评估会在建立核心库后补齐。复现要求相同输入、加工规则与数值行为；极少数处于舍入边界的浮点结果可能受平台影响，发布流水线应固定工具环境并核对输出哈希。后续需要跨平台逐字节验证。

构建先在临时目录完成编译和校验，成功后更新输出文件，清单最后写入。它不是多文件原子发布；服务部署应使用独立版本目录并切换目录引用，不在正在加载的目录直接重建。
