# UTF-8 规则数据

仅保留八类确定性数据：`symbol`、`chnum0` 至 `chnum5`、`munit`。姓名、地名、姓名排除词、词性倍率和重复字母规则已移除，不再恢复旧的通用规则解释器。

## 数据与生效方式

`src/rules.ini` 是唯一的 UTF-8 规则源，直接并列维护简繁字符和单位写法。核心同时识别两种写法，保留原文，不进行简繁转换，也不在运行时读取 INI。

| 段 | 内容 |
| --- | --- |
| `symbol` | 符号字符；结合核心已有符号范围使用 |
| `chnum0` | 零和数字零变体 |
| `chnum1` | 普通中文数字及位值字符 |
| `chnum2` | 阿拉伯数字及全角写法 |
| `chnum3` | 小数点写法 |
| `chnum4` | 金融数字写法 |
| `chnum5` | `第`、`每` 前缀 |
| `munit` | 量词、时间、金额、计量单位和百分号，每行一个，可多字符 |

字表每行可以连续写多个字符；注释以 `;` 开头。不再接受 `:tf`、`:idf`、`:include`、`:exclude`、`:attr` 等旧参数。数字字表只能使用识别器明确支持的字符，未知字符会报错，不能仅靠添加字符定义新的数值语义。单位最长 16 个 Unicode 标量，采用最长匹配。

修改数据后运行：

```sh
make
make check
```

`make` 自动生成 `generated/rules_data.h`：规则源或 `tools/gen_rules.py` 比生成文件新，或生成文件不存在时，先生成再编译。Git 开发阶段生成器依赖 Python 3；发行包已附带规则表，普通构建和运行均不需要 Python。`make rules` 保留为手动强制重新生成入口。

Git 只跟踪规则源和生成器，生成表位于已忽略的 `build/`。`make check` 校验表与源数据是否一致；规则源属于编译输入，不作为运行配置安装。更改规则需要重新构建，不能仅靠部署 INI 改变运行行为。

## 识别边界

数字识别生成参与 DAG 竞争的候选，不无条件覆盖词典。明确支持：中文数字串、位值整数、金融数字、小数、阿拉伯数字加万/亿/兆、序数及数字加单位。例如 `一九四九年`、`壹佰贰拾元`、`三点五公斤`、`第十五章`、`每三个月`、`３．５％`。

`每` 必须带明确数字和单位；单个中文数字不单独生成候选，除非带前缀或单位。暂不处理范围/约数（如“两三年”）、分数、负数、多级组合规模（如“一万亿”）、日期合法性或数值换算。数字两侧为英文字母时不强行拆开型号，原始 UTF-8 词面及偏移保持不变。

主路径选中数字组合后，搜索模式保留整体，并补出数值（`m`）和单位（`q`）；整体候选为数字 `m` 或数量 `mq`。不再从该跨度中补出“三点”“五公斤”或小数两边的零碎数字。词典整体词仍可凭代价胜出，字典补词不能跨已选中的数字边界。

符号默认不单独输出，可用 `--symbols` 保留；`￥`、`¥`、`€` 和独立的 `·` 已覆盖。词典中已有的带中点词条仍可完整匹配，不进行姓名猜测。原 `[special]` 的八个词继续由内置英文规则识别，标记为 `en`；`[nostats]` 随关键词提取一起取消。
